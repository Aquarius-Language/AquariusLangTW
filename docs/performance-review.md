**AquariusLang performance review — 2026-10-09**

Reviewed commit: `99d25fa6e427716c92fac2212f3f80096701392b`. This is an optimization inventory, with isolated measurements for selected candidates. Production source, bytecode formats, dependencies, and examples were not changed. The numbered order combines measured payoff, likely workload impact, and the size of a safe implementation. Rankings after the measured candidates are provisional; a hash-heavy program, a compute loop, and a drawing application have different bottlenecks.

S means a localized helper or hot-path edit. M means a bounded change to runtime bookkeeping or a backend, with more regression work. All candidates can retain the current compiler/stack-VM/host design and current `.rius`, bottle, and browser transport formats. No new platform-specific dependency is required.

These numbers measure individual operations or synthetic programs on this Windows machine, not application-wide speedups. Browser interpreter experiments ran in Node v24.18.0, using bytecode generated by the production C# compiler. Each isolated VM variant ran in its own Node process with 15 warmups and the median of 11 timed executions. The hash/CRC experiment used three warmups and the median of nine executions. Timing is informational. The browser sync-call change alone made the builtin-loop case slower in this run, so it should not be accepted as a blanket optimization without workload checks.

The desktop baseline allocated 28,802,424 bytes for the existing 50,000-iteration integer loop, 14,800,632 bytes for Fibonacci(20), 23,683,216 bytes for 20,000 closure calls with array writes, and 12,642,568 bytes for the builtin loop. These totals include each fresh execution and support investigating scope/call allocation; they do not prove that every allocated byte can be removed.

1. **Explicit `HashKey` equality and hashing.** [Object.cs](C:/OfficialProjects/AquariusLangTW/AquariusLangVM/object/Object.cs:64) defines a struct containing `string type` and `int value` without `IEquatable<HashKey>` or overrides. Implement fieldwise equality and a hash including both fields, or supply a consistent comparer everywhere hashes are constructed. Keep the current `(Type, Value)` key semantics, including numeric type distinctions and the existing string-to-integer hash representation. Changing string-key equality itself belongs in a separate correctness change. Runtime bucket hashes are not portable serialized IDs. Gate: object/hash tests, `VmEvaluatorTest` hash indexing/literals, serialization/application tests, and large distinct numeric-key lookup measurements.

2. **Non-throwing browser builtin lookup.** [vm.mjs](C:/OfficialProjects/AquariusLangTW/AquariusWebCompiler/browser/vm.mjs:55) catches `Scope.get` exceptions to discover normal builtins. Introduce a lookup API that returns both presence and value, and throw only after lexical scopes and builtins both miss. Preserve lexical shadowing, bound `undefined` versus absent names, and missing-name diagnostics. Gate: scope unit tests, builtin shadowing, bilingual aliases, repeated-import tests, browser/core parity, and builtin-heavy benchmarks. This is the best measured browser change of very small scope.

3. **Per-device compute cache.** [WgpuCompute.cs](C:/OfficialProjects/AquariusLangTW/AquariusDesktopVMREPL/graphics/WgpuCompute.cs:25) recompiles WGSL and creates/releases layouts and pipelines on every dispatch; [wgpu.mjs](C:/OfficialProjects/AquariusLangTW/AquariusWebCompiler/browser/wgpu.mjs) does the equivalent browser work. Cache successful compiled compute artifacts by complete source and relevant pipeline configuration, bounded per device. Recreate the resource binding for each buffer. Preserve shader errors, dispatch validation, disposal, buffer ownership, and device-loss behavior. Existing render pipelines are already cached; expanding that cache indiscriminately would duplicate existing work. Gate: repeated dispatch over different buffers, invalid WGSL, disposal, WGPU unit/integration/CLI tests, and source/bottle/browser compute examples.

4. **Capture-aware loop-scope reuse.** [VirtualMachine.cs](C:/OfficialProjects/AquariusLangTW/AquariusLangVM/VirtualMachine.cs:197) and [vm.mjs](C:/OfficialProjects/AquariusLangTW/AquariusWebCompiler/browser/vm.mjs:96) allocate a fresh scope every iteration. Recycle only scopes proven not captured, clear iteration-local declarations and inherited-write caches, and carry the loop binding exactly as today. Captures through nested scopes must mark every retained ancestor. Conservative fallback to a fresh scope is essential. Do not reuse a captured environment. Gate: `ClosuresCaptureEachLoopIteration`, enclosing-scope ownership, nested loops, break/return/error paths, nested captures, and both VM hosts. Measure allocation and throughput separately.

5. **Reusable GPU upload storage.** [WgpuTarget.Draw](C:/OfficialProjects/AquariusLangTW/AquariusDesktopVMREPL/graphics/WgpuDevice.cs:327) allocates three GPU buffers and two bind groups per draw. [BrowserTarget.draw](C:/OfficialProjects/AquariusLangTW/AquariusWebCompiler/browser/wgpu.mjs) also allocates per draw. Use bounded per-frame vertex/uniform arenas or versioned reusable chunks; retain per-draw snapshots of changed uniforms. Reusing one buffer region before the pending draws consume it would corrupt earlier draws. Respect alignment and limits, keep resources alive through submission/completion, and release arenas on resize/disposal. Gate: custom shaders, transparent compositing, contours/stencil, clip/scissor, smooth/MSAA changes, offscreen targets, ownership errors, and both rendering smoke runners. Preserve draw order; batching is a later step.

6. **Faster portable checksums.** [Serialization.cs](C:/OfficialProjects/AquariusLangTW/AquariusLangVM/application/Serialization.cs:49) processes eight CRC bit steps per byte. A table implementation gives the same checksum with one table step per byte and no hardware requirement. Adler32 at line 54 performs two modulo operations per byte; reduce modulo operations using a proven bounded block size without overflowing accumulators. Add incremental CRC state so PNG chunk checksums can cover type and payload without concatenating them. Gate: known checksum vectors, empty data, malformed/truncated document/compression tests, PNG validation, and byte-for-byte parity with the current routines.

7. **Allocation-free packing loops.** [ProcessingCanvas.Draw](C:/OfficialProjects/AquariusLangTW/AquariusDesktopVMREPL/graphics/ProcessingCanvas.cs:89) creates a 12-element temporary array for every vertex. [WgpuShaders.Uniforms](C:/OfficialProjects/AquariusLangTW/AquariusDesktopVMREPL/graphics/WgpuShaders.cs:13) creates temporary arrays for matrix fields. Write fields directly into the destination. Then consider private reusable CPU packing buffers with explicit valid lengths. Preserve the 48-byte vertex layout, matrix order, 1,120-byte uniform ABI, and per-draw snapshots. Gate: shared shader-layout tests, WGSL custom uniforms, pixel-orientation tests, rendering smoke checks. Removing the tiny temporary arrays can be a separate very small first patch.

8. **Synchronous browser fast path.** [vm.mjs](C:/OfficialProjects/AquariusLangTW/AquariusWebCompiler/browser/vm.mjs:56) makes `call` async even for closure-frame pushes; [host.mjs](C:/OfficialProjects/AquariusLangTW/AquariusWebCompiler/browser/host.mjs:16) wraps every library function in an async function. Handle Aquarius closure calls directly. For host calls, detect promise/thenable results and suspend only when necessary. Preserve public async VM entry points, rejection propagation, argument conversion/validation, real GPU/WASM/animation waits, and the current cancellation/input yielding budget. Check callback/microtask ordering explicitly. Gate: async host calls, reentry, cancellation, input/Stop, imports, real physics/GPU initialization, all browser tests, and call-heavy benchmarks. Accept only workloads with demonstrated gain.

9. **Single-probe scope reads.** [Environment.Get](C:/OfficialProjects/AquariusLangTW/AquariusLangVM/object/Environment.cs:38) and `GetOwned` perform `ContainsKey` followed by the indexer. Use `TryGetValue` while retaining the existing iterative outer-scope search and exact found/null behavior. JS maps need separate presence information for bound undefined; do not use truthiness to detect a binding. This does not require replacing the two environment dictionaries. Gate: `TestVariableScopeAndOwnership`, closures, modules, REPL, and missing-variable errors.

10. **Single owner resolution for writes.** [VirtualMachine.Set](C:/OfficialProjects/AquariusLangTW/AquariusLangVM/VirtualMachine.cs:216) searches with `Get`, then [Environment.Set](C:/OfficialProjects/AquariusLangTW/AquariusLangVM/object/Environment.cs:85) walks again. A `TrySet`/resolved-owner helper can avoid the repeated walk and update both owned and inherited-cache entries consistently. Increment can reuse a validated lookup result only where no intervening script/native call can change ownership. Compound assignment must retain the current post-RHS reread: `x += x++` produces 7 from x=3. Gate: assignment order, scope ownership/shadowing, unknown writes, and reentrant callbacks.

11. **Avoid script-call argument copies.** [VirtualMachine.Call](C:/OfficialProjects/AquariusLangTW/AquariusLangVM/VirtualMachine.cs:226) allocates an argument array before determining callee type. Bind script parameters directly from the private operand-stack segment, then clear that segment; retain owned arrays for builtin delegates. Zero-argument builtins can use `Array.Empty<IObject>()`. Hash literal construction can read its stack segment in source order and pre-size its dictionary instead of allocating a second `2*n` array. Arrays returned to scripts must still own their storage. Gate: argument order/count, duplicate hash keys, early-error side effects, deep recursion, retained builtin arguments, and reentry.

12. **Lean execution bookkeeping.** [Frame](C:/OfficialProjects/AquariusLangTW/AquariusLangVM/VirtualMachine.cs:31) eagerly allocates a loop stack for every call, including loop-free functions. Make loop bookkeeping lazy; an execution-local frame freelist can help repeated calls. Native callback invocations also allocate a new 128-slot operand stack each time; a measured pool can reduce this overhead. Each active/reentrant execution must rent distinct storage, clear all references, and return buffers on every success/error path. Never recycle environments retained by closures. Gate: 20,000-level recursion, repeated callbacks, callback reentry, nested loops, errors, and resource-retention/allocation measurements.

**Compatibility boundaries for every accepted patch**

- Keep portable contracts in core and host-specific implementations in their current projects. No Silk.NET/Jolt native dependency may enter core. Preserve the shared WGSL ABI, file-provider identities, virtual path rules, backend capability failures, and pinned dependency licenses.
- Retain integer/float/double distinctions, current overflow/divide behavior, eager boolean evaluation, compound-assignment order, Unicode/bilingual names, fresh numeric/string literal wrappers, shared alias identity, captured loop iteration identity, and persistent REPL state.
- Keep bytecode immutable/reusable with fresh execution state; caches and pools must not introduce globals shared between runs or imports. Native callback reentry keeps separate stacks. Repeated script imports execute afresh.
- Keep pre-RHS validation and later mutation checks for indexed writes. Native hosts can mutate public objects/array backing storage; removing the second bounds check without equivalent protection is unsafe.
- Retain graphics submission/resource lifetime, draw order, alpha/color conventions, readback/resize semantics, disposal/device ownership, Jolt numerical tolerances, and browser responsiveness/cancellation.
- Add only focused behavioral coverage for the newly affected boundaries. Run the existing full gate; require measured improvement in the relevant benchmark without material regressions. Avoid machine-speed pass/fail thresholds.

**Recommended implementation order**

Start with separate patches for ranks **1, 2, 6, 7, 9**. They have clear local boundaries; ranks 1, 2, and 6 have direct measured evidence. Then take rank **3** for compute-heavy applications, ranks **4, 10–13** for CPU/call-heavy applications, or ranks **5, 14–15** for drawing-heavy applications. Take rank 8 after the no-throw browser lookup change and compare its async/sync behavior carefully. Advance the remaining candidates only when profiling identifies that workload.

For each patch, compare median execution time and allocated bytes using compiler-produced bytecode with parsing separated from execution. Add workloads for large numeric/string hashes, repeated compute dispatch, draw-call-heavy frames, imports, and bulk images/documents where relevant. Measure desktop Release, real Chrome, and target Linux/macOS hosts before claiming cross-platform speedups.
